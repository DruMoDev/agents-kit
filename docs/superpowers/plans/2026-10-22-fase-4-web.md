# Fase 4: web de changelogs. Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Web privada en Cloudflare donde Dru ve, app por app, qué ha cambiado en cada repo con agents-kit y qué no ha visto aún.

**Architecture:** App Astro en modo servidor (`output: "server"`, adaptador `@astrojs/cloudflare`) en `web/`, independiente del plugin. Datos en vivo de GitHub con una sola consulta GraphQL (repos del dueño del token con `.agents-kit.json` y su `CHANGELOG.md`), cacheada unos minutos. Estado "visto" en Cloudflare KV. Imágenes de repos privados servidas por el propio worker. Protegida por Cloudflare Access, y el worker además verifica el JWT de Access.

**Tech Stack:** Node 22, Astro 7.3.6, @astrojs/cloudflare 14.3.4, wrangler 4.148.0, vitest 5.0.3, @playwright/test 1.63.0, TypeScript. Versiones exactas en `package.json` (sin `^`), con `package-lock.json`.

**Spec:** `docs/superpowers/specs/2026-10-18-agents-kit-plugin-design.md`, sección "Web de changelogs".

## Global Constraints

- Todo en `web/` con su propio `package.json`; nada de la web entra en el plugin (scripts, skills, hooks no cambian).
- Texto de la interfaz en español, neutro, sin rayas largas. Tipos: `Nuevo | Mejora | Arreglo | Interno`.
- Secretos solo como secretos de Cloudflare (`GITHUB_TOKEN`), nunca en el repo ni en `wrangler.jsonc`. `.dev.vars` en `.gitignore`.
- Ningún test toca la red: GitHub se simula; los e2e usan `DATA_SOURCE=fixtures`.
- Nada de despliegue, creación de KV en la cuenta, Access ni secretos reales: eso lo hace el controlador tras confirmar con Dru.
- Debe verse bien en móvil (360 px) y escritorio.

## Decisiones del controlador

- **Una consulta GraphQL** (`viewer.repositories(first: 100, ownerAffiliations: OWNER, isArchived: false)`, con `object(expression: "HEAD:.agents-kit.json")` y `object(expression: "HEAD:CHANGELOG.md") { ... on Blob { text } }`, más `name`, `url`, `isPrivate`, `pushedAt`) en lugar de N llamadas REST. Si hay más de 100 repos, paginar con `pageInfo`.
- **Caché:** Cache API de Workers (`caches.default`) con clave sintética y `max-age=300`; `?refrescar=1` la salta.
- **"Visto" por entrada:** id de entrada = número de PR. KV `seen:<repo>` = JSON `{"ids": [números]}`. Una entrada es nueva si su PR no está en `ids`. Abrir una entrada la marca vista; "marcar todo como visto" añade todas las actuales. La primera vez todas son nuevas.
- **Parser = contrato de los fixtures:** `tests/fixtures/changelog/*.md` del repo. Los `valido-*` dan sus entradas; en los `invalido-*` el parser ignora solo lo malformado y nunca lanza.
- **Access:** middleware que exige `Cf-Access-Jwt-Assertion` válido (JWKS de `https://<ACCESS_TEAM_DOMAIN>/cdn-cgi/access/certs`, `aud` = `ACCESS_AUD`, RS256, `exp`), con WebCrypto. Si faltan `ACCESS_TEAM_DOMAIN`/`ACCESS_AUD`, responde 503 "Access sin configurar", salvo `DEV_BYPASS_ACCESS=1` (solo dev/e2e).

## Review Focus

1. Un repo con `CHANGELOG.md` malformado o sin él no rompe la página de inicio ni la suya (tarjeta con "sin cambios" o los válidos).
2. Imágenes: solo rutas relativas bajo `docs/changelog/` con extensión png/jpg/jpeg/gif/webp, sin `..`; el repo debe ser uno de los descubiertos; otra cosa da 404. Nunca se proxifica una URL arbitraria.
3. Token sin permisos o GitHub caído: página de error clara en español, sin filtrar el token.
4. Marcar visto concurrentemente desde móvil y Mac: no pierde ids (leer-unir-escribir; aceptable la última escritura gana a nivel de lote, pero un POST nunca borra ids).
5. Texto de entradas con HTML: se escapa (markdown mínimo propio: párrafos, `código`, **negrita**, enlaces http(s), imágenes); nunca `set:html` con contenido sin sanear.

### Task 1: datos y lógica (`web/src/lib/`)

**Files:** `web/package.json`, `web/package-lock.json`, `web/tsconfig.json`, `web/astro.config.mjs`, `web/wrangler.jsonc` (KV binding `SEEN`, id de marcador `"REEMPLAZAR"`, `compatibility_date` reciente), `web/.gitignore`, `web/vitest.config.ts`, `web/src/lib/{changelog,markdown,github,seen,access,images}.ts`, `web/test/*.test.ts`, `web/fixtures/repos.json` (datos de ejemplo para `DATA_SOURCE=fixtures`).

**Interfaces (producidas):**
- `parseChangelog(text: string): Day[]` con `Day = { date: string; entries: Entry[] }`, `Entry = { type: "Nuevo"|"Mejora"|"Arreglo"|"Interno"; title: string; pr: number; url: string; date: string; body: string }` (body = markdown de la versión extendida, sin recortar el texto libre).
- `renderMarkdown(body: string, imgUrl: (path: string) => string): string`: HTML saneado.
- `fetchRepos(env): Promise<Repo[]>` con `Repo = { name; url; isPrivate; days: Day[]; lastDate: string | null }`; usa GraphQL real o `fixtures/repos.json` si `DATA_SOURCE=fixtures`; caché como arriba.
- `getSeen(kv, repo): Promise<Set<number>>`, `markSeen(kv, repo, prs: number[]): Promise<void>` (unión), `unseenCount(repo, seen): number`.
- `verifyAccess(request, env): Promise<Response | null>` (null = pasa).
- `imageAllowed(path: string): boolean`, `fetchImage(env, repo, path): Promise<Response>` (REST `GET /repos/{owner}/{repo}/contents/{path}` con `Accept: application/vnd.github.raw`, `Cache-Control: public, max-age=86400`).

- [ ] Tests vitest primero: parser contra cada fixture de `../tests/fixtures/changelog/` (cuenta de entradas exacta de `valido-completo` = 4 con título `Ajustes: más rápidos · y claros` y cuerpo con la imagen; `valido-codigo` sin entradas falsas; `valido-vacio` = 0; cada `invalido-*` no lanza y descarta solo lo malo), repo sin changelog, markdown con `<script>` escapado, `unseenCount`, `markSeen` une sin borrar, `imageAllowed` (acepta `docs/changelog/12-login.png`; rechaza `../x.png`, `docs/x.png`, `docs/changelog/a.svg`, `https://...`), `verifyAccess` con JWT firmado en el test (clave RSA generada con WebCrypto, JWKS simulado): válido pasa, `aud` errónea/expirado/sin cabecera = 403, sin config = 503, bypass = pasa; `fetchRepos` con fetch simulado mapea la respuesta GraphQL y filtra repos sin marcador.
- [ ] Implementar hasta verde (`npm test`). Commit `feat(web): datos, parser y lógica de la web de changelogs`.

### Task 2: interfaz (`web/src/pages`, `web/src/components`, `web/src/middleware.ts`)

**Interfaces (consumidas):** todo lo de Task 1.

Rutas:
- `/`: inicio. Una tarjeta por app: nombre, fecha del último cambio, número de cambios sin ver (destacadas las que tienen), ordenadas por novedades y luego por fecha.
- `/app/[repo]`: cambios por fecha, más reciente primero; cada uno en versión corta (tipo con color, título, fecha); al abrirlo (`<details>` o similar accesible) la versión extendida con capturas y ejemplos, y se marca visto (`POST /api/seen`). Filtro por tipo. Botón "Marcar todo como visto". Los nuevos llevan marca "Nuevo".
- `POST /api/seen` `{repo, prs: number[]}` → 204; repo debe existir.
- `/img/[repo]/[...path]`: imágenes según Task 1.
- `middleware.ts`: `verifyAccess` en todas las rutas.
- Errores de GitHub: página de error en español.

Diseño: usa la skill `frontend-design` (y `impeccable` para pulir) antes de escribir la UI. "Supervisual y fácil de entender": de un vistazo qué app tiene novedades. Sin frameworks de UI pesados (Astro + CSS propio; JS mínimo en cliente para marcar visto y filtrar). Modo claro y oscuro. Accesible (contraste, foco visible, teclado).

- [ ] e2e Playwright (`DATA_SOURCE=fixtures DEV_BYPASS_ACCESS=1`, servidor `astro dev` o `wrangler dev` con KV local): inicio muestra las apps de `fixtures/repos.json` con su contador; entrar en una app; abrir un cambio muestra su extendida y baja el contador al volver; "Marcar todo como visto" deja el contador a 0; filtro por tipo; viewport 360 px sin scroll horizontal.
- [ ] `npm run build` sin errores, `npm test` y `npm run e2e` en verde. Commit `feat(web): interfaz de la web de changelogs`.
